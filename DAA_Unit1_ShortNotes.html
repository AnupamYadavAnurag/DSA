01

Algorithm Basics

Definition EXAM

A well-defined computational procedure that takes input(s) and produces output(s) — a blueprint/sequence of steps transforming input into output.

5 Characteristics (Input-Output-FDE)

  • Input – 0 or more inputs
  • Output – at least 1 output
  • Finiteness – must stop after finite steps
  • Definiteness – each step precisely defined, no ambiguity
  • Effectiveness – steps must be effective enough to solve the problem

Algorithm vs Program

  • Algorithm: informal, design phase, H/W independent
  • Program: predefined syntax, coding phase, H/W dependent
  • Algorithm → Analysis (efficiency); Program → Testing (correctness)

Pseudo Code

  • High-level description without strict syntax
  • Intermediary between algorithm & program
  • Uses indentation, // for comments, standard loop constructs

Priori vs Posteriori Analysis EXAM

A Priori (Before execution)
  • Theoretical, machine-independent
  • Uses asymptotic notations
  • Gives approximate answer
  • Credit to programmer if fast
Posteriori (After execution)
  • Practical, machine-dependent
  • Does NOT use asymptotic notations
  • Gives exact answer
  • Credit to compiler/hardware
02

Algorithm Techniques

Divide & Conquer

  • Divide: Split into sub-problems
  • Conquer: Solve recursively
  • Combine: Merge solutions
  • Examples: Merge Sort, Quick Sort, Binary Search

Greedy Method

  • Makes locally optimal choice at each step
  • Used for optimization problems
  • No guarantee of global optimal in all cases
  • Feasible → Optimal → Greedy choice

Dynamic Programming

  • Solves by breaking into sub-problems
  • Stores results (memoization) — avoids recomputation
  • Follows Principle of Optimality
  • Always gives optimal solution (considers all cases)
  • Reduces time: exponential → polynomial

Backtracking

  • Brute force — tries all combinations
  • NOT suitable for optimization problems
  • Builds solution incrementally, removes failures
  • Uses state space tree + DFS exploration

Branch & Bound

  • Used for special optimization problems (NP-hard)
  • Like backtracking but uses BFS (breadth-first) on state space tree
  • Explores all permutations in worst case (exponential)

Greedy vs Dynamic Programming EXAM

Greedy

  • Best-looking choice at each step
  • No guarantee of optimal solution
  • Faster, simpler
  • No reconsideration of past choices

Dynamic Programming

  • Decision considers all sub-problems
  • Always gives optimal solution
  • More memory/time overhead
  • Uses previously solved states
03

Analysis & Complexity

Time Complexity

  • Assumes every instruction costs same constant time
  • Total Time = Σ(N × C) for all instructions
  • Machine-independent measure

Space Complexity

  • Fixed Part: constants, simple variables, code
  • Variable Part: dynamic structures, recursion stack
  • Space = Auxiliary Space + Input Space

Cases of Analysis

Best Case
Minimum steps for input size n — Big Ω
Average Case
Average steps for input size n — Big Θ
Worst Case
Maximum steps for input size n — Big O

Growth Rates (Slowest → Fastest)

O(1) O(log n) O(n) O(n log n) O(n²) O(n³) O(2ⁿ) O(n!)

Leading term (highest degree) defines the order of growth. e.g. T(n)=5n²+3n+5 → O(n²)

04

Asymptotic Notations EXAM

Big O — O(g(n))   UPPER BOUND / WORST CASE

f(n) ≤ c·g(n) for all n ≥ n₀, c > 0

f(n) = O(g(n)) → f never exceeds c·g(n) after n₀

Most widely used. Gives maximum time an algorithm may take.

Big Ω — Ω(g(n))   LOWER BOUND / BEST CASE

f(n) ≥ c·g(n) for all n ≥ n₀, c > 0

f(n)=3n+2, g(n)=n → 3n+2 ≥ 1·n holds for c=1, n≥1 → f(n)=Ω(n)
Big Θ — Θ(g(n))   TIGHT BOUND / AVERAGE CASE

c₁·g(n) ≤ f(n) ≤ c₂·g(n) for n ≥ n₀

f(n) bounded from above AND below by g(n)

e.g. f(n)=3n+2 → Θ(n) with c₁=1, c₂=4, n₀=2

Little o   loose upper bound

f(n) = o(g(n)) means lim f(n)/g(n) = 0 as n→∞

Not asymptotically tight; rough estimate of max growth.

Little ω   loose lower bound

f(n) = ω(g(n)) means lim f(n)/g(n) = ∞ as n→∞

g(n) grows slower; not asymptotically tight lower bound.

05

Recurrence Relations

General Form

T(n) = O(1) if n ≤ c
T(n) = aT(n/b) + D(n) + C(n) otherwise

Where a = no. of sub-problems, b = factor size reduction, D(n) = divide cost, C(n) = combine cost

Substitution Method

  • Guess a bound → Prove by induction
  • Works when guessing form is simple
  • Example: T(n) = 2T(n/2)+n → O(n log n)

Iteration / Backward Sub.

  • Expand recurrence until base case
  • Express as summation of terms
  • Example: T(n) = T(n-1)+1 → O(n)

Recursion Tree Method

  • Visualize recurrence as a tree
  • Sum cost at each level → total cost
  • Best for generating a good guess
  • Disadvantage: prone to error for complex cases

Master's Theorem EXAM

For T(n) = aT(n/b) + f(n):

  • If f(n) = O(nlog_b(a)-ε) → T(n) = Θ(nlog_b a)
  • If f(n) = Θ(nlog_b a) → T(n) = Θ(nlog_b a log n)
  • If f(n) = Ω(nlog_b(a)+ε) → T(n) = Θ(f(n))

Sorting — Basics

Key Sorting Concepts EXAM

  • In-place: Uses O(1) extra space. Examples: Bubble, Selection, Insertion, Heap Sort
  • Stable: Equal elements maintain original order. Examples: Merge, Insertion, Bubble, Counting
  • Unstable: Order of equal elements not guaranteed. Examples: Quick, Heap, Shell Sort
  • Internal: All data fits in memory
  • External: Data too large for memory (e.g., Merge Sort)
  • Comparison-based: Compares elements (Bubble, Insertion, Merge, Quick, Heap)
  • Non-comparison: Does not compare elements (Counting, Radix, Bucket)
07

Comparison-Based Sorting

Insertion Sort

  • Like sorting playing cards in hand
  • Array split into sorted + unsorted; pick from unsorted, insert in correct position in sorted
  • Stable, In-place, Adaptive
CaseTimeSpace
BestO(n)O(1)
AverageO(n²)
WorstO(n²)

Heap Sort

  • Build Max-Heap → repeatedly remove root, place at end
  • Not stable; In-place
  • Complete binary tree property used
  • Left child at 2i+1, Right child at 2i+2
CaseTimeSpace
All casesO(n log n)O(1)

Shell Sort

  • Optimization of Insertion Sort — sorts elements far apart first, reduces gap gradually
  • Gap sequence: n/2, n/4…1 (basic) or Knuth's formula: h = 3h+1
  • First algorithm to break O(n²) barrier
  • Not stable; In-place
CaseTimeSpace
BestO(n log n)O(1)
AverageO(n^1.25–n^1.5)
WorstO(n²)
08

Non-Comparison Sorting

Counting Sort EXAM

  • Works when range (k) is small compared to n
  • Count frequency → cumulative count → place in output → stable
  • External sort — assumes integer inputs in range [0, k]
Steps: Count → Cumulate → Place (reverse traversal for stability)
CaseTimeSpace
All casesO(n + k)O(n + k)

Radix Sort

  • Sort digit by digit — Least Significant Digit (LSD) to Most Significant Digit (MSD)
  • Uses Counting Sort internally at each digit
  • Add leading zeros to equalize digit count
ComplexityValue
TimeO(d × (n + b))
d = digits, n = elements, b = base (10 for decimal)

Bucket Sort

  • Divides into n buckets → sort each bucket (using Insertion Sort) → concatenate
  • Works well for uniformly distributed floats in [0,1)
  • Stable (because Insertion Sort is stable)
  • bucket index = floor(n × element)
CaseTimeSpace
BestO(n + k)O(n + k)
Worst (all in 1 bucket)O(n²)
09

Quick Sort & Merge Sort

Quick Sort EXAM

  • Divide & Conquer: choose pivot → partition → recurse left & right
  • Elements < pivot → left; elements > pivot → right
  • Pivot strategies: first, last, random, median
  • Not stable; In-place; Cache-friendly; Tail-recursive
  • Most common: last element as pivot (PARTITION algorithm)
CaseTimeSpace
Best (equal split)Ω(n log n)O(log n)
AverageΘ(n log n)O(log n)
Worst (sorted array)O(n²)O(n)

Worst case: smallest/largest always chosen as pivot (e.g., already sorted array).

Merge Sort EXAM

  • Divide & Conquer: split in half → sort each half → merge
  • Stable, but NOT in-place (needs O(n) extra space)
  • Best for linked lists, external sorting, parallel processing
  • merge() function merges two sorted halves: A[l..m] and A[m+1..r]
CaseTimeSpace
All casesO(n log n)O(n)

Quick Sort vs Merge Sort EXAM

Quick Sort

  • In-place (O(log n) stack)
  • Not stable
  • Cache-friendly
  • Worst: O(n²) on sorted input
  • Faster in practice (general use)

Merge Sort

  • NOT in-place (O(n) extra)
  • Stable
  • Less cache-friendly
  • Guaranteed O(n log n)
  • Better for linked lists & external sort
